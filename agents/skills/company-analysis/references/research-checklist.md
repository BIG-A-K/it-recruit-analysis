# 企業分析調査チェックリスト

調査した事実を、比較・集計する `ir_csv` と記事本文の `mdx` に最初から分ける。IRの欠損値だけCSVスキーマの `availability` で表し、採用記事に空の表や仮置きを残さない。

## 調査台帳

| 項目 | 内容 |
| --- | --- |
| 保存先 | `ir_csv` または `mdx` |
| 値・事実 | 原文の意味を変えない要約または数値 |
| 対象 | 開示法人、連結・単体、採用主体、対象者 |
| 時点 | 基準日、会計年度、募集年度、確認日 |
| 単位 | 円、百万円、%、人、時間など |
| 出典 | 資料名、ページまたは節、URL、公表日 |

## 情報源

IRは有価証券報告書などの法定開示、決算資料、統合報告書の順で確認する。採用情報は公式採用サイトと募集要項を確認する。公式コーポレートサイト、公的データを補助に使い、一次情報で取得できない場合だけ二次情報を使う。

`yukijya_doh` の既存記事はMDXの移行元として参照できる。ただし、募集年度、職種、待遇、勤務地、働き方など変動する情報は現在の公式ページで再確認する。

## 企業境界

- 正式社名、ブランド名、証券コード、企業ID
- 親会社、持株会社、主要子会社
- 採用する法人と雇用条件の適用範囲
- 財務数値の開示法人と連結範囲
- 合併、分社化、会計基準変更による比較不能期間

## IRとしてCSVへ保存する項目

- 平均年間給与、平均年齢、平均勤続年数、従業員数など有報の人的資本情報
- 売上高、営業利益、自己資本比率
- 営業・投資・財務キャッシュフロー
- 流動資産、流動負債、当座資産と算定内訳
- 報告セグメント名、セグメント別売上・利益
- IR資料に明記された組織再編、会計基準変更、数値の比較上の注記
- 上記の根拠となるIR資料

原則3期以上の推移を集める。セグメントは開示区分を保持し、独自に統合しない。

## MDXへ保存する項目

- 理念、ミッション、企業紹介
- 公式サイト、IRページ、採用ページへのリンク
- 新卒採用の対象年度と採用主体
- 職種、仕事内容、応募資格、配属方法
- 初任給、固定残業、賞与、諸手当
- 勤務地、転勤、リモート勤務、標準労働時間
- 選考区分、応募期限など現在の募集要項
- CSVで比較しない企業固有の事業説明や補足

MDXへIR数値や年度別セグメント表を転記しない。採用情報には公式URLと確認日を近接させる。

## 更新しないCSV

- `company_profiles.csv`
- `company_messages.csv`
- `recruitment.csv`
- `segment_descriptions.csv`

これらは既存表示との互換用として読み取り専用にする。新規行、更新行、MDXからの逆同期を作らない。

## 検算

- 表の列が会計年度末か暦年かを明記したか
- 通貨、千・百万・十億の単位を統一したか
- `△`、括弧、マイナス記号を同じ意味で扱ったか
- 売上と利益で連結・単体を混在させていないか
- 流動比率を `流動資産 / 流動負債 * 100` で再計算したか
- 当座資産に棚卸資産や長期資産を含めていないか
- キャッシュフロー3区分の合計と現金増減の差を確認したか
- 企業再編や会計基準変更をまたぐ推移に注記したか
- IR行の出典IDが `sources.csv` に存在するか
- IR用CSVの主キーが重複していないか
- `availability=reported` のIR行に値、単位、出典IDがあるか
- 採用情報を採用系CSVへ書いていないか
- MDXへIR数値やCSVの表を複写していないか
- MDXの採用情報に対象年度、採用主体、公式URL、確認日があるか
- データや本文に根拠のない評価語や推測が混入していないか
