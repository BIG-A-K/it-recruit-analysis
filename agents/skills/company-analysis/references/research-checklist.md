# 調査チェックリスト

調査した事実を、最初から `ir_csv` と `mdx` に分けて記録するための台帳と、完成前の確認項目。

## 調査台帳

| 項目 | 内容 |
| --- | --- |
| 保存先 | `ir_csv` または `mdx` |
| 値・事実 | 原文の意味を変えない要約または数値 |
| 対象 | 開示法人、連結・単体、採用主体、対象者 |
| 時点 | 基準日、会計年度、募集年度、確認日 |
| 単位 | 円、百万円、%、人、時間など |
| 出典 | 資料名、ページまたは節、URL、公表日 |
| 取得経路 | 実行したCLI、引数、検索期間、フォーム、原本ID |

## 情報源

IRは有価証券報告書などの法定開示、決算資料、統合報告書の順で確認する。
採用情報は公式採用サイトと各職種の募集要項を確認する。
公式コーポレートサイトと公的データを補助に使い、一次情報で取得できない場合だけ二次情報を使う。

## 企業境界

- 正式社名、ブランド名、証券コード、企業ID
- 親会社、持株会社、主要子会社
- 採用する法人と雇用条件の適用範囲
- 財務数値の開示法人と連結範囲
- ブランド・サービス名と法人、報告セグメントの対応
- 合併、分社化、会計基準変更による比較不能期間

外資系企業は採用主体・財務開示主体・ブランドを台帳の別行にする。詳細は [`foreign-companies.md`](foreign-companies.md)。

## CSVへ保存する項目

- 平均年間給与、平均年齢、平均勤続年数、従業員数など有報の人的資本情報
- 売上高、営業利益、自己資本比率
- 営業・投資・財務キャッシュフロー
- 流動資産、流動負債、当座資産と算定内訳
- 報告セグメント名、セグメント別売上・利益
- IR資料に明記された組織再編、会計基準変更、比較上の注記
- 上記の根拠となるIR資料

原則3期以上の推移を集める。セグメントは開示区分を保持し、独自に統合しない。
どのキーをどこまでそろえるかは [`mdx-template.md`](mdx-template.md) の一覧に従う。

## MDXへ保存する項目

- 理念、ミッション、企業紹介
- 公式サイト、IRページ、有価証券報告書または海外法定開示、採用ページ、新卒採用ページへのリンク
- 新卒採用の対象年度と採用主体
- 職種、仕事内容、応募資格、配属方法、職種ごとの勤務地
- 初任給、固定残業、賞与、諸手当
- 転勤、リモート勤務、標準労働時間
- 選考区分、応募期限など現在の募集要項
- セグメント区分ごとの具体的なサービス名・ブランド名
- 親会社、主な子会社と各社の事業内容・報告セグメント
- CSVで比較しない企業固有の事業説明や補足

## 検算

- 表の列が会計年度末か暦年かを明記したか
- 通貨、千・百万・十億の単位を統一したか
- 海外開示の原通貨、会計基準、会計年度末、フォーム種別を記録したか
- 実行したCLIのコマンド、原本ID（`doc_id` またはCIK+アクセッション番号）を記録したか
- `△`、括弧、マイナス記号を同じ意味で扱ったか
- 売上と利益で連結・単体を混在させていないか
- 親会社連結、報告セグメント、日本法人単体を混在させていないか
- 親会社の従業員数、報酬、財務を日本法人の値として保存・表示していないか
- 海外提出者IDを日本の証券コードやEDINETコードへ流用していないか
- `company_relations.csv` の関係に公式出典と有効期間があるか
- 円換算値を表示する場合に原通貨、レート、基準日、出典を再現できるか
- 流動比率を `流動資産 / 流動負債 * 100` で再計算したか
- 当座資産に棚卸資産や長期資産を含めていないか
- キャッシュフロー3区分の合計と現金増減の差を確認したか
- 企業再編や会計基準変更をまたぐ推移に注記したか
- IR行の出典IDが `sources.csv` に存在するか
- IR用CSVの主キーが重複していないか
- `availability=reported` のIR行に値、単位、出典IDがあるか
- 採用情報をレガシーCSVへ書いていないか
- MDXへIR数値やCSVの表を複写していないか
- 基準給与・基礎給・固定時間外手当の内訳が合計と一致するか
- 標準年収が月給の何か月換算かを確認し、12か月と異なるなら注記したか
- 各職種の勤務地が募集要項と一致し、共通条件は適用職種が明確か

## 記事の充足

- `CompanyProse` とコンポーネントを交互に配置し、テンプレート外の見出しを足していないか
- 企業理念・ミッションを公式表記で書き、引用元URLと確認日を近くに置いたか
- `## サイト` にHP、IR、法定開示（取得した全年度）、採用、新卒のリンクをそろえたか
- 新卒の職種別勤務地・待遇を表にしたか（共通条件は適用範囲を明記し、記載がない場合のみ確認できた職種区分と募集要項の所在を文章で書いたか）
- 表の `※n` と `:::info` の定義が対応しているか
- 表と見出し・ディレクティブの間に空行があるか
- `## サービス例` を具体名で埋め、その直後に説明を重複しない `SegmentRevenue` を置いたか（セグメント別売上が非開示ならコンポーネントを省いたか）
- `SegmentRevenue` の後の `## 関連企業` を具体名で埋めたか（該当がない場合は見出しごと省いたか）
- 読者への助言、評価、推測を書いていないか
- `HealthMetrics` の3キーが最新期にそろっているか
- 棒グラフ用の `metric_key` が3期以上そろい、空のグラフが出ないか
- `FinancialHistory` と `MetricTrends` を分けて配置し、`FinancialData` を新規に使っていないか
- 埋められなかった要素を、空の表ではなく報告として扱ったか
