# 外資系企業・海外開示主体

日本で採用する法人と、財務を開示する海外親会社を同一企業として扱わない。

## 3層に分ける

調査開始時に次の3層を確定する。

| 層 | 例: AWS | 保存先 |
| --- | --- | --- |
| 日本の採用主体 | Amazon Web Services Japan合同会社 | 採用主体の `companies.csv` 行とMDX |
| 海外の財務開示主体 | Amazon.com, Inc. | 開示主体の `companies.csv` 行とIR用CSV |
| ブランド・報告セグメント | AWS | 開示主体を `company_id` とする `segments.csv` |

1. 採用主体と開示主体に別々の `company_id` を付ける。両法人の法的関係と有効開始日を公式資料で確認できる場合だけ、`company_relations.csv` の `parent` などで結ぶ。ブランドとしての関係しか確認できない場合や直接の法的関係が不明な場合は、確認日を `valid_from` に代用せず、関係行を作らない。表示に使う開示主体はMDXの `:::warn` で明示する。
2. 業界は、その事業で採用する法人または掲載対象の事業会社へ付与する。多角化した海外親会社へ子会社と同じ業界を自動付与しない。
3. 親会社の連結財務は親会社の `company_id` で保存する。日本法人へ複写したり、`scope` だけ変えて日本法人の数値に見せたりしない。
4. ブランドが法人でない場合は会社マスタを増やさず、法定開示上の報告セグメントとして保存する。
5. 海外親会社の従業員数・報酬を、日本法人の従業員数・平均給与・待遇として扱わない。日本法人単体の法定開示がなければ、採用情報はMDXに記録し、IR指標は欠損理由を報告する。

## 海外法定開示の取得

1. 開示国、規制当局、提出者ID、上場市場、ティッカー、会計年度末を特定する。海外識別子を `securities_code` や `edinet_code` へ流用しない。現行スキーマに保存先がなければ、スキーマ・読み込み処理・整合性テストを先に拡張する。
2. **開示国に対応する既存CLIがある場合だけ進む。** CLIがなければ、その場限りの取得スクリプトやIR行の手入力へ進まず、当該規制当局向けの共通クライアント・正規化ルール・CLI・テストを実装してから再実行する。
3. 通常は最新の年次報告書を処理し、その比較情報から取得可能な最新3期以上を保存する。四半期報告や期間内の全書類はユーザーが明示したときだけ対象にする。
4. `sources.csv` には提出者・フォーム種別・アクセッション番号など、原本を一意に識別できる情報を保存する。企業IRサイトの年次報告書は照合または補完に使う。
5. 財務指標には原資料の通貨と会計基準を保存する。**円換算値を正本としてCSVへ保存しない。** 表示時に換算する場合も、原通貨・換算レート・基準日・レート出典を併記する。

## SEC標準経路（米国上場企業）

Form 10-K（米国国内発行体）または20-F（外国民間発行体）を正本とする。どちらかはSubmissions APIの提出履歴で確認し、推測しない。
`SEC_USER_AGENT` は組織名と監視可能な連絡先を含めて `.env` に設定する（SECのFair Access Policy）。

Form 20-Fは、対象企業の会計基準に対応する正規化ルールが実装済みであることをテストで確認してから処理する。CLIが `taxonomy is unsupported` と停止した場合はIR行を手入力せず、IFRSなど対象タクソノミーの共通正規化ルールとテストを先に実装する。

```bash
uv run --env-file .env sec-fetch <disclosure_company_id> \
  --start <YYYY-MM-DD> \
  --end <YYYY-MM-DD> \
  --form 10-K
```

検索期間はSKILL.mdフェーズ2の規則で決める。通常は期間内の最新年次報告書だけを処理し、`--all` はユーザーが明示したときだけ追加する。

`sec-fetch` は原本を `data/raw/sec/<CIK>/<accession-number>/` に保存し、アクセッション番号を使って主キーupsertする。同じ原本が保存済みでも再ダウンロードせず、正規化とupsertは再実行する。

APIを使わず取得済み原本を再変換する場合だけ、原本ディレクトリと対応する `sources.csv` 行の存在を確認して次を実行する。

```bash
uv run sec-normalize <disclosure_company_id> <accession-number>
```

報告セグメントにディメンション情報が必要なら、対応するInline XBRL原本を解析する。

`sec-fetch` / `sec-normalize` が未実装、あるいは対象フォーム・指標・セグメントに未対応なら、**そこでIR収集を停止する。** 共通クライアント・正規化ルール・CLI・テストを実装してから再実行する。その場限りのスクリプト、ブラウザからの転記、別コマンドで代替しない。

## 記事の表示要件

- 日本法人のMDXを採用情報の正本とし、採用主体・対象年度・確認日を明記する。
- 親会社IRを表示するときは開示主体のCSVを参照し、日本法人の `company_id` へ数値を複写しない。
- `BusinessSegments` では開示企業が公表したセグメント名と区分を保ち、ブランド売上を独自推計しない。
- 親会社連結と事業セグメントの数値を同じ表に混在させず、対象範囲を分けて表示する。
- 日本企業との比較では、通貨・会計基準・会計年度末・連結範囲の差を常に表示する。
- 開示主体の違い、単純比較できない条件、重要な欠損、通貨換算など読者の解釈を誤らせる注意は、通常の段落に埋もれさせず `:::warn` に入れる。補足だけなら `:::info`。

```markdown
:::warn
以下の財務情報は海外親会社の連結業績であり、日本法人単体の業績ではありません。
:::
```
